# 系统架构说明

## 1. 设计目标

本项目基于 vn.py 构建面向研究、回测和模拟交易的事件驱动平台。

设计重点：

- 运行环境隔离与依赖可复现；
- 策略、数据、交易接口和风控模块解耦；
- 回测显式纳入手续费和滑点；
- 运行配置、数据库和密钥不进入公开版本库；
- Web 管理台默认只读，交易执行能力与公网隔离。

## 2. 当前架构

```text
┌─────────────────────────────────────────────┐
│                scripts/                     │
│  环境验证 │ 演示数据入库 │ 无 GUI 回测       │
└───────────────────┬─────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────────┐
│                  vn.py                       │
│ EventEngine → MainEngine → OMS               │
└───────┬────────────────────┬────────────────┘
        │                    │
        ▼                    ▼
┌───────────────┐    ┌────────────────────────┐
│ strategies/   │    │ vnpy_sqlite             │
│ 双均线 CTA    │    │ .vntrader/database.db   │
└───────────────┘    └────────────────────────┘
3. 组件职责
组件	职责
EventEngine	使用线程安全队列分发行情、订单、成交和定时事件
MainEngine	管理网关、功能引擎和应用模块
OMS	维护最新 Tick、委托、成交、持仓、账户和合约状态
CtaTemplate	定义策略生命周期及下单接口
BacktestingEngine	加载历史数据、逐条回放、撮合和计算绩效
vnpy_sqlite	保存和查询 K 线、Tick 及数据概览
RiskManager	后续接入的事前下单限制模块
Web 管理台	后续提供脱敏、只读优先的状态和回测展示


4. 数据与回测流程
K 线数据
  → SQLite 数据库
  → BacktestingEngine 加载
  → CtaTemplate.on_bar()
  → 模拟订单与成交
  → 手续费 / 滑点 / 每日盯市计算
  → 收益、回撤、夏普等统计指标
